Everyday commands

Everyday commands

This page lists devvm’s commands in the groups that devvm --help shows them in, and each row links to the page with the details. devvm COMMAND --help shows a command’s examples and flags, the command line covers what works the same in every command, and the CLI reference has every command with all its flags.

Your VM

devvmopen a shell in this folder’s VM, at the same path, making the VM first with the toolchains, agents and layers you choose, or that --tools, --agents and --layers name (details)
devvm restartstop this folder’s VM, start it again and open a shell in it, for changes that apply only when it starts (details)
devvm stopstop this folder’s VM (details)
devvm update [--force] [--no-export] [--clean-home]move this folder’s VM to the newest shared tools, and when its image or its devcontainer.json has changed, make it again from the image’s new build and the file as it is now, keeping its home folder and settings, after asking, then open a shell in it (details)
devvm rm [--force] [--no-export] [--no-clone-check]delete this folder’s VM after asking, exporting its agents’ history first unless --no-export (details)
devvm rm VM [--force] [--no-export] [--no-clone-check]delete a VM whose folder is gone, by its name or ssh alias, after asking (details), or one whose folder is on a disk that isn’t connected, only after asking in a terminal (details)
devvm adoptuse the VM made for an earlier folder at this path here (details), or the VM made for this folder before you moved or renamed it (details)
devvm adopt VMmove a VM whose folder is gone to this folder, such as a copy of that folder on another disk, after asking (details)
devvm lslist the project VMs (details)
devvm codeget this folder’s VM ready as devvm host does, then open its folder in VS Code over Remote-SSH (VS Code)
devvm desktop [--clipboard] [--no-open]serve this folder’s VM’s desktop on 127.0.0.1 with its password until Ctrl+C, and open it in Screen Sharing on macOS (details)
devvm hostget this folder’s VM ready for ssh and editors, and show the host name they reach it by, such as devvm-website (details)
devvm historylist the exports of agents’ history that devvm saved in ~/.local/share/devvm/exports (details)
devvm history export [FILE]save the history of this folder’s VM’s agents to FILE, or to a new .tar.gz in ~/.local/share/devvm/exports (details)
devvm history import [FILE]put the agents’ history in FILE, or in the newest export devvm saved for this folder, into this folder’s VM (details)
devvm paste [--json] [--send-file]send the image, the PDF, or the one copied file, after asking about a file, on this machine’s clipboard into this folder’s running VM’s paste folder, and copy its path there for your terminal’s paste shortcut (details)
devvm paste rm [--force]delete the files devvm paste left in this folder’s running VM, after asking (details)

In a folder without a VM of its own, each of these commands but devvm adopt uses the VM of the nearest folder with one that it’s inside, and says which VM that is. --here and --parent choose which VM a command uses (a subfolder).

These options are for a new VM, so a VM that exists ignores them with a warning, and only devvm takes them (what a new VM gets):

--tools LIST|nonethe toolchains the VM gets, such as --tools node,python, in place of those the folder’s files call for (details)
--agents LIST|nonethe coding agents the VM gets, such as --agents claude,codex, in place of those devvm setup chose (details)
--layers LIST|nonethe layers the VM’s image gets, bottom first, such as --layers docker, in place of those devvm setup chose (details)
--network TIERcreate the VM on a network tier: open reaches anything this machine can, internet any public host, allowlist, the default, only the hosts you allow, and none only its agents’ and secrets’ hosts and its links
--clonecreate the VM with its own clone of the repo, or of each repo in a folder of repos, instead of mounting the folder (details)
--repos all|none|LISTwith --clone in a folder of repos, the repos the VM gets a clone of, such as --repos frontend,backend, in place of the picker (details)
--no-git-protectcreate the VM without .git protection
--ssh-agentcreate the VM forwarding your SSH agent, so while you’re connected, anything in it can use your keys (details)
--unsafe-foldermount a folder that devvm refuses, such as one that is or holds your home folder (details)
--cpus N, --memory GiB, --disk GiBthe VM’s size (details)
--ports all|none|LISTwhich ports the VM forwards (details)
--from IMAGEstart its base from a container image, such as node:24, instead of Ubuntu’s cloud image (details)
--no-devcontainercreate the VM without reading the folder’s devcontainer.json, which otherwise describes the VM as far as devvm supports it, with the options you give taking priority (details)

Working on a clone

devvm --clonemake this folder’s VM with its own clone of the repo, copy your repo into it and open a shell in the clone (details)
devvm clone fetch [--json]on this machine, fetch the VM’s work as devvm/<branch> into every repo it has a clone of, with its Git LFS objects, to review before you merge it, and list the new or moved branches, each with its repos (details)
devvm clone add PATHcopy one more repo of a folder of repos into the VM, at the same path (details)
devvm rmdelete the VM, first offering to keep the work you haven’t fetched as saved/devvm/<branch> branches (details)
devvm clone on|offmake an existing VM again with its own clone of the repo, or with the folder mounted once devvm has offered to keep the clone’s work as devvm rm does (details)

Change your VM

devvm toolsin a terminal, choose this folder’s VM’s toolchains and agents in a list, then open a shell in it, and otherwise show its shared tools, each with its version and any newer one (details)
devvm tools add TOOL...add shared tools to this folder’s VM, such as devvm tools add python claude, then open a shell in it (details)
devvm tools rm TOOL...take shared tools out of this folder’s VM, such as devvm tools rm python claude, then open a shell in it
devvm tools updatemove this folder’s VM to the newest shared tools, and only those, then open a shell in it (details)
devvm size [--cpus N] [--memory GiB] [--disk GiB]show or change this folder’s VM’s CPUs, memory and disk (details)
devvm size -g ...show or change the size new VMs get (details)
devvm mount-cache [none]show how this folder’s VM caches its project folder on a Linux host, none, which new VMs get, or Lima’s mmap, which can lose writes, or switch it to none from the VM’s next start (details)
devvm ports [all|none|LIST]show or change which ports this folder’s VM forwards to this machine’s localhost, even while it runs (details)
devvm ports add|rm LISTforward more ports, or stop forwarding some (details)
devvm ports -g ...show or change what new VMs forward (details)
devvm network [open|internet|learn|allowlist|none]show this folder’s VM’s tier, open, internet, internet (learning), allowlist, none or unenforced, and then its allowlist, file by file, or give it a tier: between the confined tiers at once, and into or out of open from its next start, offering to restart a running VM now, and with learn, internet while it learns the hosts it needs (details)
devvm network -g [open|internet|allowlist|none]show or change new VMs’ tier, which is allowlist until you change it (details)
devvm network lock [--all] [--none]choose which of the hosts this folder’s VM learned it keeps, add them to its own rules, and give it the allowlist tier (details)
devvm network allow|deny|rm RULE... [-g]add allow or deny rules to this folder’s VM’s own, or remove them, at once, and with -g, change yours for every VM (details)
devvm network allow|deny|rm RULE... --method METHODS --path PATHnarrow those rules to some of a host’s requests, such as only GET and HEAD (details)
devvm network log [--follow] [-n N] [--blocked]show what this folder’s VM connected to and what its proxy blocked (details)
devvm network transparent [on|off]show whether this folder’s VM sends tools that ignore the proxy settings to its proxy by the names they look up, and where that comes from, or give the VM its own setting, from its next launch (details)
devvm ssh-agent [on|devvm|off]show this folder’s VM’s SSH agent forwarding, which is off, on for yours or devvm for devvm’s own, then the keys devvm’s own agent holds and those added to it, or change the forwarding from the VM’s next start (details)
devvm ssh-agent add KEY_FILE [--confirm] [--lifetime DURATION]load a key into devvm’s own agent, and load it again whenever a VM needs it (details)
devvm ssh-agent rm KEY_FILEtake a key out of devvm’s own agent, so devvm doesn’t load it again (details)
devvm git-protect [on|off]show or change this folder’s VM’s .git protection, while it’s stopped (details)
devvm clone [on|off] [--force] [--no-export] [--clean-home] [--no-clone-check] [--repos LIST]show whether this folder’s VM has its own clone of the repo, or make it again with one, or with the folder mounted, keeping its home folder and settings, after asking, then open a shell in it (details)
devvm secret, devvm secret rm NAMElist the secrets, whether each is saved and the VMs using it, or delete a saved one (details)
devvm secret set claude|github [--stdin]save your Claude Code token or GitHub token on this machine, so that VMs get a placeholder and their proxy puts the secret in (details)
devvm secret set NAME --host HOST --env VARIABLEsave a secret of your own, such as an API key, which VMs that use it send only to its hosts (details)
devvm secret use|unuse NAMElet this folder’s VM use a secret, or stop it, though a VM with Claude Code always uses claude (details)
devvm layer add LAYER... [--force] [--no-export] [--clean-home]make this folder’s VM again with more layers on top, keeping its home folder and settings, after asking, then open a shell in it (details)
devvm layer rm LAYER... [--force] [--no-export] [--clean-home]make this folder’s VM again without some of its layers, keeping its home folder and settings, after asking, then open a shell in it (details)

Links between VMs

devvm linklist this folder’s VM’s links, each with its name, port, target VM and folder, the target’s status, and whether the link applies (details)
devvm link add TARGET PORT [--as NAME]link this folder’s VM to PORT of the VM that TARGET names, so programs in it reach the port as NAME:PORT and NAME.devvm.internal:PORT (details)
devvm link rm TARGET PORTremove one of this folder’s VM’s links (details)
devvm link publish [PORTS]show the ports this folder’s VM publishes, or offer PORTS to links from any of your other VMs (details)
devvm link unpublish PORTSstop offering ports to links (details)
devvm groupshow the group this folder’s VM is in, with each of its VMs, the name the others reach it by, its folder and the ports it publishes (details)
devvm group join NAME [--as NAME]put this folder’s VM in the group NAME, which its first VM makes, so each VM in the group reaches the ports the others publish (details)
devvm group leavetake this folder’s VM out of its group, removing the links the group made (details)

Images

devvm imageslist the images, then the shared tool images (details)
devvm images rm IMAGE|KEY...delete images, by name or by the key devvm images shows (details)
devvm build IMAGEbuild an image and the images under it, unless they’re built, such as devvm build docker or devvm build foo+bar, where IMAGE is base or layers and never a shared tool (details)
devvm rebuild IMAGEbuild an image of base or layers again from its parent as it is, and delete the stale images no VM uses, while shared tools follow the tools lock instead (details)
devvm layer new NAMEstart a layer of your own, ~/.config/devvm/layers/NAME.sh, with its allowlist, NAME.policy (details)

devvm build, devvm rebuild and devvm images rm take --from IMAGE to work on a base made from that container image (details).

Disk space

devvm spaceshow what devvm keeps on this machine, the disk each kind takes, and what frees it (details)
devvm gcdelete the stale and unfinished images and the tool images no VM uses, after listing them, and never a VM (details)
devvm retention [KEY=VALUE...]show the retention settings, which say what devvm deletes on its own, or change them, with KEY=off turning one off (details)

This machine

devvm setup [--features LIST|none] [--agents LIST|none] [--layers LIST|none]choose base’s features and the coding agents and layers new VMs get, and in a terminal also new VMs’ size and network tier (details)
devvm agent import [AGENT...]copy the agents’ settings and logins from your home folder into devvm’s agent store, which every VM gets them from, never their history, asking before it replaces the store’s (details)
devvm agent login AGENT [--setup-token] [--device-code] [--api-key]log an agent in inside this folder’s VM, such as Claude Code to your Claude subscription, or get a Claude Code token with --setup-token (details), or log an agent in to ChatGPT there, in a browser on this machine or with a code, or save an API key, and keep the login in devvm’s agent store for every VM (details)
devvm agent save [AGENT...]copy the agents’ settings from this folder’s VM into devvm’s agent store, never their logins or history, after showing what changed and asking (details)
devvm doctorcheck what devvm needs on this machine and say how to get what’s missing (details)
devvm upgrade [--check] [--to VERSION]install devvm’s newest release the way you installed devvm, after asking, or with --check only say whether a newer one is out (details)
devvm completion SHELLprint the shell completion script for bash, zsh or fish (details)
devvm limactl ARGS...run Lima’s limactl on the VMs and images in devvm’s own Lima home, not ~/.lima, for debugging, which starts VMs unconfined, whatever their tier (details)

devvm itself

devvm help [COMMAND]print the help for devvm or a command, as --help and -h do (details)
devvm --versionprint devvm’s version alone, as devvm version also does

The folders devvm keeps its state in and the environment variables it reads are in Settings and files.
